# T22 Visit pack + return link: two-way coordination with no accounts (headline feature)
Problem: grandparents and sitters can see a plan but nothing flows back, and real-time sync needs accounts. Solution: a one-home "visit pack" link goes out; the helper ticks items on their own phone (no install, no account); they tap "Send back" which makes a tiny reply link; the parent opens it and the plan merges. Everything travels in URL fragments (never reaches a server).
Part A (pure logic, src/share/): schema VisitPack {v:1, packId, homeName, childAge band, tasks:[{id, title key/hazardId, room, status, updatedAt}], from: first name}; Reply {v:1, packId, by: first name, updates:[{taskId, status, at}]}. encodeVisitPack/decodeVisitPack, encodeReply/decodeReply (same codec rules as T7: deflate + base64url, Zod strict, size cap, redaction: no full names, birthdates, emergency cards). mergeReply(localTasks, reply): apply only updates whose `at` is newer than local updatedAt, ignore unknown task ids, never downgrade 'done' to 'todo' unless newer; returns {tasks, summary:{applied, ignored, by}}. Tests: idempotent (applying twice changes nothing), out-of-order, tampered, unknown ids, size cap, no private data in either link.
Part B (UI, after Part A): People tab: "Send a visit pack" per home (native share sheet or copy link) and a pending list of packs sent. Helper view /visit (opened from link): shows the pack read-only except tick boxes, stores state locally (separate IndexedDB key), big "Send back" button -> share sheet with the reply link, plus the printable briefing. Parent: /merge opens from a reply link, shows "Grandma finished 3 tasks" with a confirm button, then merges. Copy plain and warm; mention that nothing is uploaded.
Done when typecheck, lint, tests pass; Part A can be delivered alone first. Reply <150 words.
